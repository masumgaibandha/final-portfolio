This file is a template, not a published article. It stays out of production
because `draft: true`, and it is here so you have a working reference to copy.

## Adding a new post

Create `content/blog/your-slug.mdx`. The filename becomes the URL, so
`cold-email-infrastructure.mdx` is served at `/blog/cold-email-infrastructure`.

Set `draft: false` when it is ready. Drafts are visible while running
`npm run dev` and excluded from `npm run build`, so you can preview a post
before anyone else can reach it.

## Every published article needs a cover

A post cannot go out with `draft: false` unless it has **both** of these. The
build fails naming the file and the missing fields, and there is no fallback
artwork — the cover is the card image on `/blog` and the article's social
preview, so a generated placeholder would misrepresent the piece.

```yaml
coverImage: "/blog/your-slug/cover.webp"
coverAlt: "Describe what the image actually shows"
```

Write `coverAlt` as a real description; it is read aloud by screen readers and
shown if the image fails to load. Covers render in a 16:9 media area with
`object-cover`, so around 1200×675 works well.

A draft may omit both, which is why this template has them commented out. If a
draft does carry a `coverImage`, it still needs `coverAlt`.

## Adding other images

Put them in `public/blog/your-slug/`, then reference them from the web root:

```mdx
![A short, meaningful description of the image](/blog/your-slug/diagram.webp)
```

## Formatting

Ordinary Markdown works, and everything picks up the site's styles:

- Bulleted lists
- **Bold** and `inline code`
- [Internal links](/projects) and [external ones](https://nextjs.org)

> Block quotes are set in the editorial italic with a terracotta rule.

Frontmatter is validated at build time, so a malformed date or a missing
description fails the build with the filename rather than shipping broken
metadata.
